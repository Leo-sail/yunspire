### RRF 融合算法

**完整实现** ✅

```
最终分数 = 词法RRF + 向量RRF + 额外信号

RRF 公式:
- 词法RRF = 1 / (60 + rank)
- 神经RRF = 2.0 / (60 + rank)
- 本地RRF = (0.5 或 1.0) / (60 + rank)

额外信号:
- 标题完全匹配: +12
- 标题包含: +8
- 路径包含: +6
- 标签匹配: +4
- 链接匹配: +3
- 时效性: +3/+2/+1
```

## 💡 关键决策

### 1. 为什么不迁移查询函数？

**原因**:
- runtime_db.rs 中实现稳定（已生产验证）
- 迁移复杂度高（~352 行 + 依赖函数）
- 收益有限（主要逻辑已在 SearchPlugin）
- 风险较高（涉及 FTS5 和向量计算）

**决策**: 保持现状，查询函数作为依赖使用

### 2. 为什么创建桥接层？

**原因**:
- Tauri Command trait 是同步的
- 搜索需要异步操作
- 避免重复定义 #[tauri::command]

**决策**: bridge.rs 提供 indexed_search_impl()

### 3. 为什么 RRF 在 core_search.rs？

**原因**:
- 核心搜索逻辑独立
- 避免 algorithm.rs 过大
- 便于后续优化

**决策**: core_search.rs 负责融合和排序
