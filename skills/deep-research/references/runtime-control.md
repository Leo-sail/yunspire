# 运行控制契约

## 目录

- 控制循环
- 策略决策
- 预算核算
- 取消语义
- 检查点
- 恢复与幂等
- 终止状态

## 控制循环

在每个阶段边界、每次 Vault 读取前后、每次模型调用前后执行同一组检查：

1. 确认任务 ID、研究 ID 和请求修订号仍与当前运行一致。
2. 检查取消令牌是否已触发。
3. 重新读取适用的策略决策及其缩减范围。
4. 计算已用预算与本次最小原子操作的最坏情况成本。
5. 只有全部通过时才执行操作。
6. 原子记录结果、预算增量、内容哈希和幂等键。

不得在检查与调用之间替换任务信封。检测到修订号变化时停止当前阶段，保存检查点并要求基于新修订重新规划。

## 策略决策

把 Policy Engine 的结构化结果作为最终授权：

- `deny`：立即返回 `policy_denied`，记录规则级原因，不寻找替代路径绕过策略。
- `allow_with_reduced_scope`：把缩减后的 Vault、来源类型、阶段和预算覆盖到运行上下文，只在新范围内继续。
- `requires_approval`：完成当前最小原子记录后写检查点，返回 `awaiting_checkpoint`；等待期间不消耗 Vault、网络或模型预算。
- `allow`：继续执行，但仍应用任务预算、取消和来源规则。

当前 schema 固定网络访问为关闭、外部交付为关闭、Vault 写入为关闭、认证访问为拒绝。不得用空白策略字段解释为默认允许。

## 预算核算

分别跟踪：

- 已用时间与截止时间。
- 已接受和已读取来源数量。
- 网络请求数与下载字节数；当前两者上限都必须为零。
- 模型调用次数。
- 模型输入和输出 token。

在接近上限时停止扩展查询，只完成已开始的最小原子步骤并写检查点。若下一操作的最坏情况成本可能越界，则不得发起该操作。达到任一上限时返回 `budget_exhausted`，并在 `budget_usage.limit_reached` 中标识具体预算项。

不得通过拆分请求、重试、恢复或子任务重置预算。重试成本计入同一研究预算。

## 取消语义

一旦观察到取消：

- 不再发起 Vault 读取、模型调用、引用生成或后续阶段。
- 允许完成当前不可分割的本地持久化，以保存一致检查点。
- 返回 `cancelled`，并指明最后完整阶段和安全检查点引用。
- 不追加未经完整引用校验的部分综合结论。

取消优先于重试和阶段推进。不得因为取消发生在模型返回后就自动消费或提交该返回值；先核对调用是否属于已取消修订。

## 检查点

在计划、证据批次、矛盾、综合、引用和反思阶段结束后写检查点。至少记录：

- 研究 ID、任务 ID、请求修订号和阶段。
- 输入指纹、策略决策指纹和幂等键。
- 预算累计用量与记录时间。
- 已接受的 `source_id`、结果对象哈希和前一检查点引用。
- 阶段完成状态及等待审批原因。

不要写入凭据、完整来源正文、未脱敏本地绝对路径或无关用户数据。检查点只能引用受控存储中的来源和证据记录。

## 恢复与幂等

只在以下条件全部满足时恢复：

- 研究 ID、任务 ID、请求修订号和输入指纹一致。
- 当前策略仍允许原范围，或允许一个可明确缩减的范围。
- 检查点链和结果哈希完整。
- 取消令牌未触发，截止时间和预算仍可继续。
- 来源时效仍满足策略。

恢复后重新执行策略、取消、时效和预算检查。使用原幂等键识别已经提交的 Vault 读取和模型调用；不得重复计费或重复追加证据。检查点损坏或范围不匹配时返回 `failed` 或从最后一个更早的有效检查点恢复，不得猜测状态。

## 终止状态

- `completed`：六个阶段完成，最终验证通过，`termination` 为 `null`。
- `awaiting_checkpoint`：等待明确的人工审批或输入，已保存可恢复状态。
- `cancelled`：取消已被观察，后续调用已停止。
- `budget_exhausted`：至少一个硬预算到达上限。
- `policy_denied`：策略拒绝当前研究或后续阶段。
- `needs_review`：研究产物存在引用、来源、矛盾或完整性问题，不可标为完成。
- `failed`：发生结构化错误；记录错误代码、是否可重试和最后安全检查点。

重试必须复用同一幂等键并遵守剩余预算。不得用新的任务包装掩盖旧任务的失败或超支。
